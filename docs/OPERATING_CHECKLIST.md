# Moots Operating Checklist

## Purpose

This checklist governs the next phase of the Moots Forever Frame project after the governance layer has been established.

The project is no longer treated as a cycling website. It is a governed brand system with memory, territory enforcement, execution routing, signal intelligence, and doctrine continuity.

---

## Priority 1 — Stabilize Production Site

Verify before making major new changes:

- SSL active everywhere
- No redirect loops
- No broken forms
- Canonical tags point to `https://mootsframe.com/`
- Sitemap is valid and submitted/indexed
- Robots.txt does not block intended pages
- All auxiliary domains use HTTPS 301 redirects to `https://mootsframe.com/`
- All functional inquiry paths route cleanly through the approved execution layer

Do not rebuild the site during this phase. Stabilize first.

---

## Priority 2 — Put Future Copy Through Doctrine

All future outward-facing copy must reference the governance docs before publication:

- `docs/DOCTRINE.md`
- `docs/TERRITORY_AUTHORITY.md`
- `docs/SIGNAL_RULES.md`

Applies to:

- Captions
- Landing sections
- Email confirmations
- Event pages
- Dealer outreach
- Form labels
- CTA language
- Metadata and SEO descriptions

Doctrine governs tone. Territory authority governs routing. Signal rules govern presence.

---

## Priority 3 — Begin Territory Signal Capture

Use the Signals Hub to capture raw territory intelligence before proposing action.

Initial signal tracks:

- Austin ride intelligence
- Bentonville partner mapping
- Oklahoma City event opportunities
- Dealer status tracking
- Pop-up timing
- Partner availability
- Regional rider behavior

Signals create awareness. Systems determine action.

---

## Governance Rule

No execution output should be generated until it has passed through:

1. Doctrine
2. Territory Authority
3. Signal Rules

This protects against reactive messaging, spec contamination, tone drift, and routing confusion.
